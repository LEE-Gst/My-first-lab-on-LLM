# NL 中间层实验报告

## 实验目的

验证"自然语言 → LLM 解析 → 结构化中间层 → 可验证执行"这条路：
LLM 只负责把自然语言 DFA 规则解析成结构化规格，长程状态复合交给确定性/可学习执行器。

## 设置

- DFA：k=4，m=2，接受状态 2 个，随机排列转移。
- 字符串长度：L ∈ {8, 16, 32}，每配置 15 个样本。
- NL 描述模板：
  - **T1 表格式**：状态/起始/接受 + "A -0-> B" 逐条转移。
  - **T2 规则式**：逐状态 "In state A, on symbol 0 go to B, ..."。
  - **T3 打乱+同义词**：转移顺序打乱，动作/连词用同义词替换。
- LLM：qwen2.5:7b（Ollama，temperature=0）。
- 四条件：
  - A 纯 LLM 直接（NL + 字符串 → 逐位状态）
  - B 纯 LLM CoT（逐步推理）
  - C LLM 解析 → JSON spec → **确定性算法**执行
  - D LLM 解析 → JSON spec → **Neural DFA Executor**（232K，Phase 2 训练）执行
- 指标：全轨迹准确率（每一步状态都对才算对）。

## 结果

| 配置 | parse_ok | A 直接 | B CoT | C 解析+算法 | D 解析+Executor |
|---|---|---|---|---|---|
| T1 L=8 | 1.00 | 0.00 | 0.00 | 0.93 | 0.93 |
| T1 L=16 | 1.00 | 0.00 | 0.00 | 0.93 | 0.93 |
| T1 L=32 | 1.00 | 0.00 | 0.00 | **1.00** | **1.00** |
| T2 L=8 | 1.00 | 0.00 | 0.00 | 0.80 | 0.80 |
| T2 L=16 | 1.00 | 0.00 | 0.00 | 0.73 | 0.73 |
| T2 L=32 | 0.93 | 0.00 | 0.00 | 0.67 | 0.67 |
| T3 L=8 | 0.67 | 0.00 | 0.00 | 0.40 | 0.40 |
| T3 L=16 | 0.80 | 0.00 | 0.00 | 0.33 | 0.33 |
| T3 L=32 | 0.80 | 0.00 | 0.00 | 0.40 | 0.40 |

## 结论

1. **纯 LLM 执行彻底失败**（A、B 全 0.00）：qwen2.5:7b 在 k=4、L=8 的 DFA 全轨迹追踪上就完全无法完成，
   即使 CoT 也一样。这与 M0 基线（α_struct=0）一致，且这里 L=8 就暴露。
2. **中间层（C/D）显著胜出**：一旦 spec 解析成功，执行是完美的（长度无关：
   T1 在 L=32 达到 1.00，比 L=8 还好）。
3. **C ≡ D 完全等价**：Neural DFA Executor 与手写确定性算法输出完全一致——
   Executor 是"可学习的正确执行器"，可以替代需要手写规则的算法层。
4. **瓶颈 = LLM 解析**：T1 表格解析率 100% → C 0.93~1.00；T2 规则式 0.67~0.80；
   T3 打乱+同义词 0.33~0.40。执行层从不是瓶颈。

## 对"中间层"设计的启示

- 架构 = **LLM（解析/决策窄接口）+ 结构化中间层（可验证、可审计、长度无关）**。
- 概率性 LLM 只做"从自然语言到形式语言"的一小步；所有需要串行复合的工作
  （状态追踪、流程执行、数值累计）都交给确定性/可学习执行器。
- 这正好承接 M0/Phase1/Phase2 的完整链条：
  Transformer/LLM 无法可靠做 δ* 复合（M0 证实）→ 纯学习受限于规格解析（Phase 1）
  → 显式记忆执行器解决复合（Phase 2）→ LLM 只需负责 NL→结构（本实验）。

## 后续可做

1. **提升解析率**：few-shot 示例、qwen2.5-coder:7b（更擅长输出 JSON）、
   一致性校验重试（多个解析结果投票）、利用 delta 必须是排列的先验做纠错。
2. **更大 k 与更长 L**：解析 + 执行层理论上都长度无关，验证 L=100+。
3. **verdict 级指标**：全轨迹对才计数太严，可加"最终接受/拒绝判定"指标。
4. **推广到一般任务**：把同样的"LLM 解析 + 状态机中间层"用到
   对话流程控制、API 编排、代码生成验证等。
