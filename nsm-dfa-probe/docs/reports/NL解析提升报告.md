# NL 解析提升报告（v2）

## 动机

NL 中间层的唯一瓶颈是 LLM 解析率。本实验测试四种手段：
1. **排列先验纠错**：每个符号的转移列必须是 [0..k-1] 的排列，最小编辑修复（重复→缺失）。
2. **few-shot**：给 1 个 k=2 的 NL→JSON 示例。
3. **多解析投票**：temperature=0.3 采样 3 次，k/start/accepting/delta 逐项多数投票。
4. **换模型**：qwen2.5-coder:7b（代码模型更擅长结构化输出）。

## 解析消融（k=4，每模板 15 样本）

| 策略 | T2 exact | T3 exact |
|---|---|---|
| 零样本 qwen（v1 基线） | 0.53 | 0.33 |
| 零样本 + 排列纠错 | 0.67 | 0.33 |
| few-shot qwen | 0.33（**变差**） | 0.00（**变差**） |
| 投票×3 qwen | 0.67 | 0.47 |
| 投票×3 + 纠错 | 0.73 | **0.53** |
| few-shot **coder** | 0.87 | 0.20 |
| few-shot coder + 纠错 | **1.00** | 0.47 |

**要点**：
- 排列纠错稳定 +0.1~0.2（T2: 0.53→0.67，FS-coder: 0.87→1.00）。
- few-shot 对 qwen2.5:7b **有害**（示例是 T2 风格，T3 打乱句反而被示例带偏）——few-shot 示例必须与目标格式同构。
- coder 模型在 T2（规则式，与示例同构）上近乎完美。
- 投票对 T3（最难）最有效（0.33→0.47）。

## 端到端对比（v1 vs v2，全轨迹准确率 C/D）

每模板用最佳策略：T1/T2 → few-shot coder + 纠错；T3 → 投票×3 + 纠错。

| 配置 | v1 C | v2 C | 提升 |
|---|---|---|---|
| T1 L=8/16/32 | 0.93/0.93/1.00 | **1.00/1.00/1.00** | 满 |
| T2 L=8 | 0.80 | **0.87** | +0.07 |
| T2 L=16 | 0.73 | **1.00** | +0.27 |
| T2 L=32 | 0.67 | **0.93** | +0.26 |
| T3 L=8 | 0.40 | 0.40 | 0 |
| T3 L=16 | 0.33 | **0.40** | +0.07 |
| T3 L=32 | 0.40 | **0.47** | +0.07 |

- T2 平均 0.73 → **0.93**（+0.20）。
- T1 达到 1.00（解析 100% + 执行 100%）。
- T3 仍最难（打乱句 + 同义词 + 隐含主语），投票+纠错小幅提升到 0.47。
- **D ≡ C 仍然完全一致**：Executor 在任何解析结果上都与确定性算法等价。

## 结论

1. **结构化中间层在 T1/T2 上已接近完美**（0.93~1.00），长度无关（L=32 全对）。
2. **纯 LLM 执行依然全败**（A/B = 0.00 所有配置）。
3. 解析率提升的三板斧按性价比排序：
   **排列先验纠错（免费）> 换 coder 模型（结构化输出更强）> 多解析投票（成本×3，对付最难的打乱句）**。
4. few-shot 模板必须与目标输入同构，否则负收益。
